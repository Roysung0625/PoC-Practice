# 안전한 로컬 실습

[교육 안내](README.md) · [실행 안내](../../analysis-chatbot/README.md) · [장애와 검증 읽기](FAILURE_AND_VERIFICATION.md)

이 실습은 설치가 끝난 현재 Windows 환경을 전제로 한다. 새 PC에서는 먼저 [설치·시작 안내](../../analysis-chatbot/README.md)를 따른다. 아래 명령은 문서의 예시이며 이 문서를 작성하며 서비스·AWS·DB를 실행하거나 변경한 것은 아니다.

## 1. 먼저 상태와 비용 경계를 확인한다

프로젝트 루트의 PowerShell에서 확인한다.

```powershell
.\analysis-chatbot\scripts\Status.ps1
.\analysis-chatbot\scripts\Check.ps1
```

`Status.ps1`은 소유 프로세스·공유 수신기·웹 포트와 API 상태를 보여준다. `Check.ps1`은 로컬 API·DB 읽기 연결·웹·가시화 환경을 확인한다. 이 결과가 정상이더라도 AWS 인증·실제 모델 추론·Lambda 왕복이 확인됐다는 뜻은 아니다.

웹이 중지돼 있고 진행 중인 분석·평가가 없다면 시작한다.

```powershell
.\analysis-chatbot\scripts\Start.ps1
```

브라우저에서 [로컬 분석 챗봇](http://127.0.0.1:8010)을 연다. Python API 주소는 `http://127.0.0.1:8001`이다. 기본 바인딩은 로컬 인터페이스이며 인터넷 공개 실습을 하지 않는다. `Start.ps1`은 호환되는 기존 API를 재사용할 수 있고, 소스 수정 후 기존 프로세스가 자동으로 새 코드를 읽는다고 보장하지 않는다.

| 화면에서 하는 일 | SQL 읽기 실행 | AI/AWS 사용 |
| --- | --- | --- |
| 저장 대화 열기·상태 확인 | 새 승인 SQL 없음. 상태 검사에는 로컬 DB 연결 확인이 포함될 수 있음 | 모델 추론 없음 |
| `로컬 연결 검사 (AI 아님)` 계획 보기 | 승인 전 조회 없음 | AWS 없는 고정 계획 |
| 로컬 연결 검사 승인 | 고정 읽기 SQL 실행 | AI 추론·AWS 왕복 없음 |
| AI 모드에 질문 보내기 | 승인 전 조회 없음 | 해석·문서 계획에서 이미 유료 모델 호출 가능 |
| 허용 오류의 승인 전 초안 보완 | SQL 실행 없음. 같은 문서·고정 조건에서 한 번만 보완 | 기존6회·180초 안에서 추가 유료 모델 호출 가능 |
| AI 계획 승인 | 승인된 SQL이 AWS→Windows 경로로 실행 | Agent·Lambda·SQS·DynamoDB·모델 등 사용 |
| `다른 그래프로 보기` | 저장 결과 사용, SQL 재실행 없음 | 현재 재시각화 경로는 독립 로컬 PNG 처리 |
| `다시 설명하기` | 저장 결과 사용, SQL 재실행 없음 | AI 결과는 모델 호출 가능. 로컬 샘플 결과는 결정적 로컬 설명 |
| `후처리만 다시 시도` | SQL 재실행 없음 | 선택한 단계에 따라 AI 설명 재호출 가능 |
| 기간·필터·상세 범위를 바꾸는 후속 질문 | 새 계획·승인 후 새 조회 | AI 모드이면 모델 호출 가능 |

월 **25 USD** 기준은 프로젝트 하나가 아닌 AWS **계정 전체의 실제 집계 비용 초과** 감지다. **10 USD 알림은 보존**한다. Budgets→SNS→제어 Lambda와 15분 점검을 사용하지만 집계·감지 지연 사이에 비용이 초과될 수 있어 정확한 청구 상한이 아니다. root·서비스 연결 역할·제어 역할은 일반 IAM 차단에서 제외되며 일부 실행 자원만 중지 지원한다. 중지 후 저장소·스냅샷·IP·구독 등의 비용이 남을 수 있고 다음 달 자동 복구도 하지 않는다. 앱과 수신기는 일반 최소 권한 역할을 사용한다. 교육 실습으로 예산을 낮추거나 차단·복구를 시험하지 않는다. 기준은 [예산 정책](../../aws/config/budget-policy.json), 절차와 한계는 [예산 제어 안내](../../aws/budget_guard/README.md)에서 확인한다.

## 2. 고정 샘플로 화면 흐름을 배운다

1. 새 대화에서 `로컬 연결 검사 (AI 아님)`를 선택한다. 자연어를 바꿔도 SQL은 고정 검사임을 확인한다.
2. `분석 과정`에서 서버 이벤트와 실제 읽은 문서 목록을 본다. 내부 추론을 추측하지 않는다.
3. 승인 화면에서 테넌트·문서 상태·기간·지표·통화와 SQL·매개변수를 읽는다. 알고 있는 질문의 조건과 다른 계획이라면 실행하지 않고 취소한다.
4. `확인 · 조회 실행`을 눌러 읽기 조회를 승인한다. 표와 각 검증, PNG의 값·단위를 따로 읽는다.
5. 화면을 새로고침하고 같은 대화를 다시 연다. 표·이벤트·이미지가 남는지 확인한다.

학습 기록에는 비밀 값 대신 `계획 승인 전/후`, `행 수`, `차트 단위`, `각 검사 상태`, `참조 결과 ID 연결 여부`처럼 필요한 관측만 쓴다. 내부 토큰·AWS 자격 증명·DB 비밀번호·실제 DSN을 복사하지 않는다.

## 3. 저장 결과를 재사용한다

성공한 결과의 `다른 그래프로 보기`에서 **이미 반환된 열** 중 가로축·값을 고른다. 존재하지 않는 열을 새로 조회하는 기능이 아니다. `다시 설명하기`도 저장된 표를 사용한다. 새로운 턴과 파생 `result_id`는 생기지만 원본 표와 승인 plan은 보존한다.

관찰할 점은 다음과 같다.

- 재사용 턴이 같은 대화의 원본 `source_result_id`를 가리키는가?
- COUNT로 지표를 바꾸면 금액 단위를 그대로 쓰지 않고 `건`으로 표시하는가?
- 명세를 누락해 호스트가 기본 차트를 골랐다면 그 선택 사실이 계획 검증에 보이는가?
- 다른 x/y/type을 명시 선택했는데 과거 기본선택 설명이 현재 그래프의 선택 근거로 남지 않는가?
- 원본 표가 바뀌지 않고 `SQL 재실행 없음`으로 표시되는가?

표의 행 수가 그대로라는 관찰만으로 SQL 미실행을 증명할 수는 없다. 구현상의 경계는 [`Analysis.reuse`](../../local/python/poc/analysis_api.py#L449)가 SQL 실행 함수를 호출하지 않는다는 점이다. 별도 검증에서는 [저장·재사용 회귀](../../local/python/tests/test_analysis_chart_defaults.py)나 원장의 전후 SQL 작업 수도 확인한다. 교육 실습에서 원장 파일을 직접 편집하지 않는다.

## 4. 유료 AI 실습은 준비 상태를 확인한 뒤 한 번씩 한다

AWS 배포·인증·일반 역할·예산 제어가 준비됐고 다른 평가가 진행 중이지 않을 때 운영 안내를 따른다. 필요한 경우에만 수신기를 포함해 시작한다.

```powershell
.\analysis-chatbot\scripts\Start.ps1 -Receiver
```

같은 큐를 읽는 Windows/Mac 수신기를 동시에 운영하지 않는다. Windows의 중복 실행 잠금은 다른 PC의 소비자까지 자동 통제하는 기능이 아니다.

AI 모드 질문 예시:

> GardenWorld의 활성 상품을 상품 유형과 판매 가능 여부별로 세고, producttype·issold 원본 코드와 상품 수를 보여줘.

이 문장은 학습용 요청 예시다. 특정 정답이나 성공을 보장하지 않는다. 해석·문서·계획을 먼저 읽고, `ad_client_id`, 활성 조건, 그룹 열과 `COUNT`를 확인한 뒤 승인한다. 계획이 확인 질문으로 멈추면 답변하거나 취소한다. 계획을 얻기 위해 같은 질문을 반복 제출해 성공한 것만 남기지 않는다.

승인 전 초안이 거부되고 보완되는 이벤트를 보게 된다면 다음을 관찰한다. 일부러 실패를 만들거나 모델 호출을 반복해서 이 화면을 유도하지 않는다.

1. 첫 거부 코드와 시도 번호가 남는가? 후속 보완은 미승인 date/timestamp 범위·`isactive`를 막는 `UNAPPROVED_SCOPE_FILTER`를 포함한 허용 오류6종에만 최대1회이며 기존6호출·180초를 초기화하지 않는다.
2. 거부 초안에서 파생한 조건이 다음 시도의 확정 조건으로 넘어가지 않는가? 같은 문서·원조건에서 검증한 최종 계획을 읽는다.
3. 보완 초안이 통과해도 아직 조회 전임이 표시되는가? 최종 SQL·조건·시도 요약을 포함한 최신 digest만 승인한다.
4. `첫 초안 검증 통과`와 `첫 초안 거부 후 보완 통과`가 구분되는가? 보완 실패나 출력 잘림도 기록에 남아야 한다.

v13용 소스는 계획 출력 상한4,096토큰과 출력 잘림 거부를 사용한다. 출력 상한을 늘렸다고 무조건 계획이 성공하지 않으며 잘린 JSON을 임의로 이어붙여 승인하지 않는다. 추가 보완은 AI 비용이 생길 수 있지만 SQL 실행 권한을 주는 행위는 아니다. v13의 실제 보완은1회 실패·성공0회였으며 후속 수정의 실제 모델 성공은 아직 확인되지 않았다. 로컬 모의 시험과 [최신 실제 검증](../../analysis-chatbot/docs/VERIFICATION.md)을 구분한다.

후속 차트 정규화를 관찰할 때는 비quoted SQL 별칭 `거래처_ID`가 실제 PostgreSQL 출력 `거래처_id`에 대응하는지, quoted 이름은 그대로 보존되는지 확인한다. 통화가 분할 기준이면 비통화 그룹 전체가 라벨에 남아야 한다. 수량·COUNT 차트의 USD/EUR별 이미지 분리는 값의 단위가 달러·유로라는 뜻이 아니다. COUNT는 `건`, 증명하지 못한 수량 표현식은 `단위 미검증`을 유지한다. 현재 중간 파일은 JSON이며 CSV 변환 기능을 실습하는 단계가 아니다.

전체 라이브 평가 명령은 [독립 정답 평가 안내](../../analysis-chatbot/evaluation/README.md)에서 별도로 읽는다. 라이브 평가는 유료 모델 호출과 실제 승인 SQL 조회를 수행하므로 일상적인 상태 점검 명령처럼 실행하지 않는다.

## 5. 장애를 읽고 복구한다

| 관찰 | 먼저 할 일 | 보존해야 할 것 |
| --- | --- | --- |
| 웹/API 연결 끊김 | 저장 대화 확인→상태 스크립트→해당 프로세스 로그 | 이전 표·이벤트·이미지·요청 ID |
| 표는 있고 PNG만 실패 | `visualization` 검사와 오류 코드 확인, 필요한 후처리만 재시도 | 승인 SQL과 원본 표 |
| 설명만 실패 | 관측 근거/형식 검사를 확인, AI 재호출 비용 고려 | 원본 표·성공한 PNG |
| 첫 계획 초안 거부·보완 이벤트 | 허용 코드·시도 이력·최종 상태를 확인. 보완 초안도 검증 실패하면 종료 | 첫 실패·시도 요약·최종 승인 대상의 구분 |
| 수신기/인증/PC 문제로 도구 대기 실패 | 명시적 실패와 원장 결과 확인. 빈 결과로 취급하지 않음 | 요청 ID·실행/전달 상태 |
| 서비스 재시작 후 `interrupted` | 이전 SQL 실행 여부·저장 결과부터 확인 | 불확정 작업 증거. 자동 재실행하지 않음 |

로그 위치는 `.local/analysis-chatbot/logs/`와 `analysis-chatbot/storage/logs/`다. 인증 갱신은 별도의 운영 절차이며 웹 재시작만으로 AWS 임시 인증이 갱신되지 않는다. 민감한 로그 전체를 그대로 공유하지 않는다.

승인 후 SQL 실패를 승인 전 초안 보완으로 되돌려 자동 재실행하지 않는다. 새 SQL이 필요하면 새 계획과 승인을 받아야 한다. 사용자가 선택하는 후처리 재시도는 저장된 원본 결과에만 적용하며 SQL을 실행하지 않는다.

실습을 마치고 **진행 중인 작업이 없을 때** 이 실행 스크립트가 시작한 프로세스만 중지한다.

```powershell
.\analysis-chatbot\scripts\Stop.ps1
.\analysis-chatbot\scripts\Status.ps1
```

재사용한 API·수신기와 PostgreSQL 서비스는 이 스크립트의 소유 대상이 아닐 수 있다. 해당 프로세스를 시작한 원래 운영 스크립트로 관리한다. 데이터 파일을 지워 장애를 해결하는 방식은 사용하지 않는다.

## 복습

1. `다시 설명하기`가 SQL을 실행하지 않으면 무료인가?
2. 샘플 모드에서 입력한 기간을 바꾸면 그 기간으로 AI가 분석했는가?
3. `Check.ps1` 정상인데 AI 조회가 실패할 수 있는가?
4. 보완한 계획이 통과했으므로 승인 버튼을 누르지 않아도 조회가 시작되는가?

<details>
<summary>답 확인</summary>

1. AI 결과의 재설명은 모델 호출 비용이 발생할 수 있다. SQL 미실행과 AWS 미사용은 다른 조건이다.
2. 아니다. 샘플은 고정 계획·SQL 검사다. 입력 자연어 변경을 이해했다고 판단하지 않는다.
3. 그렇다. 로컬 연결 점검과 실제 AWS 인증·모델·Lambda 왕복은 검사 범위가 다르다.
4. 아니다. 보완은 승인 전 계획 작성이다. 최종 계획의 최신 digest를 명시적으로 승인해야 SQL 실행을 요청한다.
