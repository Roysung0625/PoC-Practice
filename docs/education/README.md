# 이 프로젝트로 배우는 DB 분석 챗봇

이 문서는 `PoC-Practice`의 현재 소스를 읽고, 로컬 화면과 검증 기록을 이해하기 위한 학습 안내다. 대상 데이터는 iDempiere의 GardenWorld 데모다. 실제 기업의 운영 실적이나 순이익을 분석한 것으로 해석하지 않는다.

**작성 기준은 2026-11-04의 v13 실제 평가와 그 후속 로컬 보완이다.** v13 실제10문항은 독립 수치9/10, 수동 전체 기준4/10 통과로 종료됐다. 첫 초안9개 통과·1개 거부, 실제 보완1회 실패·보완 성공0회다. 이후 저장된4문항에서 PNG7개를 복구한 결과는 새 코드의 오프라인 검증이며 원본 실제 평가의 실패 판정을 성공으로 바꾸지 않는다.

최신 실행 버전·검사 범위·남은 실패는 [검증 기록](../../analysis-chatbot/docs/VERIFICATION.md)과 원본 평가 자료에서 확인한다. 후속 차트·미승인 필터 보완을 적용한 새 실제 통합 평가는 별도로 필요하다. 소스 수정, 오프라인 회귀 통과, 실제 AWS 왕복은 서로 다른 증거다.

## 학습 범위

- Laravel/Vue는 대화 화면과 복원을 담당하고, Python API는 문서·조건·승인·SQL 실행 검증을 담당한다.
- AWS AgentCore의 DeepSeek V3.2가 질문 해석·계획·관측 설명에 참여한다. Lambda는 승인된 SQL을 Windows에 전달하고 **동일한 도구 호출의 응답**으로 결과 또는 실패를 반환한다.
- PostgreSQL은 업무 데모 데이터, 두 SQLite는 웹 대화와 SQL 승인·실행 상태, 독립 Matplotlib 패키지는 검증된 표의 PNG를 담당한다.
- 화면의 `분석 과정`은 서버가 기록한 단계·시각·이벤트다. 모델 내부 추론을 그대로 보여주는 기능이 아니다.
- 승인 전 첫 초안이 허용된 검증 오류로 거부되면 같은 문서·조건에서 한 번 보완할 수 있다. 후속 미승인 범위 필터 검사까지 포함한 허용 목록은6종이다. 최초 실패를 지우지 않으며 전체 검증을 통과한 최종 digest만 승인한다. 보완은 기존6회·누적180초 안의 추가 AI 호출이며 비용이 발생할 수 있다.
- 로컬 연결 검사는 실제 DB의 고정 읽기 조회다. AI 질문 이해나 AWS 전체 연결의 성공을 증명하지 않는다.

## 첫 복습

1. 차트가 실패했는데 표가 남아 있다면 SQL도 실패한 것인가?
2. SQL을 승인하기 전에 AI 비용이 생길 수 있는가?
3. Python 테스트 수백 개가 통과하면 실제 AWS 10문항도 모두 정답인가?
4. 보완한 두 번째 초안이 통과하면 첫 초안도 성공했다고 기록하는가?

1. 아니다. 원본 조회 성공과 PNG 후처리 실패를 구분한다. `partial`과 개별 단계 검증을 읽는다.
2. 그렇다. 질문 해석·문서 계획 단계에서 이미 모델을 호출한다. 승인 버튼은 SQL 실행의 경계다.

4. 아니다. `첫 초안 거부→보완 후 계획 검증 통과`를 구분한다. SQL 실행에는 별도로 최종 계획 승인이 필요하다.
