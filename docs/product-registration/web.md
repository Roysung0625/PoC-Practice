# 일본어 상품 등록 웹

상품 등록은 분석 대화와 분리된 `/products/new`에서 진행합니다. 기존 왼쪽 메뉴의 `商品登録`으로 이동하며, 등록 화면의 `分析チャット` 링크로 돌아옵니다. 기존 분석 대화의 SQL 승인·저장 흐름은 유지합니다.

## 사용 흐름과 데이터 출처

1. **商品を説明**: 자유 설명을 서버에 보내 이름·용도·입수·단위 표현·중량·설명 중 실제 추출된 항목을 보여 줍니다. 사용자가 확인한 후에만 상품 초안에 반영합니다. 설명 없이 직접 입력할 수도 있습니다.
2. **類似商品を選ぶ**: 후보는 최대 10개입니다. 상품명·카테고리·용도·입수·기본 단위·선택적 중량을 유사 이유와 별도로 항상 표시하며, 값이 없으면 미입력을 명시합니다. 서버가 제공한 유사 이유를 표시하며 검색 실패와 정상 0건을 구분합니다. `この商品を参考に入力` 또는 `コピーせずに入力`으로 진행합니다.
3. **商品情報を入力**: 상품 코드·이름·설명·카테고리·단위·세금·용도·중량·입수를 편집합니다. `自分の入力` → `説明から確認済み` → `参考商品から` 순서로 우선하며, 사용자가 지운 값도 수동 입력으로 보존합니다. 참조 허용 항목은 상품명·설명·카테고리·단위·세금·용도·중량·입수입니다. 수동 입력이나 확인된 설명으로 보호되지 않은 상품명은 참조 상품의 이름으로 보완합니다. 사용자가 명시적으로 비운 이름도 수동 입력으로 보호합니다. 상품 코드·상품 ID·SKU·감사 정보·프로모션 정보는 복사하지 않습니다.
4. **検査・登録**: 상품과 함께 생성할 마스타를 검토하고 서버 규칙 검사를 실행합니다. 반환된 문제를 모두 표시하고 클릭하면 해당 입력에 초점을 맞춥니다. 유효한 검사 토큰과 검사 당시의 입력·규칙 버전이 일치할 때만 `登録する`로 등록할 수 있습니다. 오류에는 `修正する` 버튼과 항목·메시지를 포함한 접근 가능한 이름을 제공합니다.

설명의 `unit_text`는 서버에서 읽어 온 마스타 명칭과 NFKC 정규화 후 정확히 일치할 때만 기존 단위 ID로 연결합니다. `1トレー6ポット`의 입수와 거래 단위를 혼동하지 않습니다. 일치하지 않는 단위는 자동 생성하지 않고 사용자가 기존 단위를 선택하거나 신규 생성하도록 안내합니다. 카테고리와 단위는 코드·명칭, 세금은 명칭을 화면에서 신규 작성할 수 있으며 최종 등록까지 DB에 저장하지 않습니다.

오른쪽 도움말은 단계별 안내와 `?` 항목 설명, 자유 질문을 같은 서버 규칙에서 가져옵니다. 선택한 후보의 실제 검색 이유도 오른쪽 대화에 남깁니다. 검사가 거부되면 문제마다 실제로 전송한 값·서버 메시지·규칙 ID·버전을 표시하고 해당 입력으로 이동할 수 있습니다. 이 피드백에는 추가 모델 호출이나 오류별 네트워크 요청을 사용하지 않습니다. 답변에 실제 규칙 ID·버전을 표시하며 입력으로 이동할 수 있습니다. 도움말은 초안 값을 변경하지 않습니다. 좁은 화면에서는 입력 영역 아래에 배치하여 가로 넘침을 방지합니다.

## 요청 흐름과 보안

```text
Vue /products/new
  -> 동일 출처 POST /api/product-registration/{action} + CSRF
  -> 고정 action 목록을 검사하는 Laravel 컨트롤러
  -> 기존 PythonApi (루프백 호스트 / 서버측 내부 토큰)
  -> POST /v1/product-registration/{action}
```

`action`은 `normalize`, `search`, `masters`, `help`, `validate`, `register`, `status`만 허용합니다. 각 동작의 최상위 전달 필드도 고정합니다. HTTP 상태와 JSON 오류 `detail.code/message`를 유지하며 통신 장애는 503으로 표시합니다. 상위 서버의 쿠키나 인증 헤더는 전달하지 않습니다. 브라우저에 내부 API 토큰을 넣지 않습니다. 요청 본문은 64 KiB로 제한합니다.

HTML 입력의 문자열과 API의 수치 타입은 다릅니다. `wireDraft()` 경계에서 유효한 입수는 정수, 중량은 수치, 선택 ID는 정수로 변환하고 비어 있는 선택적 중량은 null로 보냅니다. 잘못된 값은 서버가 항목별 문제를 설명할 수 있도록 보존합니다. 검사한 JSON을 그대로 등록·같은 UUID 재전송에 사용합니다. 검색에는 이름·설명·용도·단위 표현·양수 입수/중량만 보내며 코드·마스타 ID·빈 수치 문자열은 보내지 않습니다. 빈 검색 조건도 PHP 전달 후 JSON 객체로 유지합니다.

설명의 단위가 `鉢`인데 기존 마스타에 없다면 단위가 미해결인 상태를 확인된 설명의 출처로 보호합니다. 유사 상품의 `Each` 등 다른 단위로 조용히 대체하지 않으며 사용자가 선택·신규 작성해야 합니다.

상품 API에 한해 Laravel의 문자열 trim·빈 문자열 null 변환을 제외하여 검사와 재전송의 원문이 달라지지 않게 합니다. 최종 판정과 DB 트랜잭션은 Python이 담당합니다. CSRF와 기존 로컬 접속·Origin 제한은 유지합니다. Bedrock 응답을 기다릴 수 있도록 PythonApi의 해당 경로만 최대 120초이며 기존 분석 API의 8초 제한은 유지합니다.

## 변경·장애와 복구

등록에 성공하고 영수증을 새로고침하면 상품 코드와 검색 반영 상태를 복원합니다. 오른쪽 도우미도 영수증에 따라 검색 대기 또는 검색 가능 상태를 표시합니다. 초안 재검사 안내는 아직 전송하지 않은 초안을 복원할 때만 표시됩니다.

- 입력을 수정하거나 도움말에서 새 규칙 버전을 받으면 검사 토큰을 무효화합니다. 서버가 `RULE_VERSION_CHANGED`를 반환하면 저장한 버전을 비우고 최신 규칙으로 다시 검사합니다.
- 최초 등록 전에 UUID와 정확한 초안·규칙 버전·검사 토큰을 `sessionStorage`에 저장합니다. 응답 유실이나 5xx에서는 해당 내용을 유지하며 입력을 잠그고 `登録状況を確認` 또는 `同じIDで再送`을 제공합니다. 새로고침 후에도 같은 UUID로 복구합니다.
- 확정적인 입력·검사 오류는 재검사로 돌아갑니다. `REQUEST_CONFLICT`는 기존 요청이 있으므로 해당 UUID의 상태 확인 흐름을 유지합니다.
- `index_status=pending`은 상품 저장 성공과 검색 반영 대기를 구분해 표시합니다. 상태 확인으로 `indexed`가 확인되면 검색 반영 완료로 표시합니다.
- 제출 전 `下書きを破棄`로 상품·신규 마스타 초안, 출처, 이전 요청 상태와 도움말 대화를 비우고 1단계로 돌아갈 수 있습니다. 등록 요청이 미확정이면 이 버튼을 숨깁니다. 이 동작은 DB 상품·마스타를 생성하지 않습니다.
- 초안은 현재 브라우저 탭 범위입니다. 영구 서버 초안이나 여러 기기 사이의 동기화 기능은 제공하지 않습니다.

## 라벤더 등록의 실제 로컬·AWS 연동 확인

별도 승인 후 2026-11-08 14:19 JST에 실제 `http://127.0.0.1:8010/products/new`에서 일본어 설명부터 등록·검색까지 한 번 수행했습니다. 모의 응답을 사용하지 않은 별도 결과입니다.

- 실제 `PKG-01` 도움말과 입수 0의 검사 거부, 6으로 수정한 최종 통과가 모두 같은 S3 v2 규칙 버전임을 확인했습니다. 오류 링크가 입수 입력으로 초점을 옮겼습니다.
- 실제 후보 `POCJA-0041 / ラベンダー コンパクト`를 참조하고 카테고리 `Bushes`와 세금 `Standard`의 기존 ID 107을 유지했습니다. 후보의 단위 `Each`가 설명의 `鉢`를 덮어쓰지 않았으며 신규 단위 `POT / 鉢` 하나만 함께 작성했습니다.
- `GW-LAV06 / ラベンダー苗・6鉢`, 용도 `ベランダ`, 입수 정수 6, 선택적 중량 null로 검사를 통과한 정확한 JSON을 한 번 등록했습니다. 상품 ID는 `1000200`, 요청 UUID는 `7d318ae8-e77f-491a-9226-dfb9076d574f`입니다. 다른 상품 코드나 새 UUID로 재시도하지 않았습니다.
- 실제 화면에서 `indexed`와 검색 반영 완료를 확인했습니다. 이후 같은 출처의 실제 검색 API는 신규 상품을 반환했으며 일본어 전문 검색·의미 검색 모두 1위였고 입수 6 일치 이유도 포함했습니다.

이어 실제 Chrome으로 `バレンタイン用花`를 등록했습니다. `GW-VAL01`과 신규 분류 `GWFLOWER`가 함께 저장됐고 새 초안의 동일 검색에서 상품 ID `1000201`이 1위로 반환됐습니다. 신규 세금 분류 생성과 저장 실패는 격리 DB에서 검증했습니다. [원본 대조와 Chrome 검증 기록](verification.md)
