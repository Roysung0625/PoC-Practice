# 일본어로 라벤더 상품 등록하기

GardenWorld에서 기본 단위가 화분 한 개(`鉢`)인 라벤더 모종을 등록한다. 여섯 개를 한 포장으로 묶어도 재고의 기본 단위는 화분 한 개다. 입수는 6이고, 중량을 입력한다면 화분 한 개의 kg 값이다. 필드별 안내와 화면 검사는 같은 S3 규칙 버전을 읽는다.

## 시작 전

프로젝트 루트에서 PowerShell 7을 연다. [설치·실행 안내](README.md)에 따라 웹과 Python 패키지를 먼저 준비한다. **최초 환경**에서는 등록 전용 DB 계정과 운영 테이블을 준비하고 [AWS 설정 안내](../../aws/registration/README.md)에 따라 S3 규칙을 게시한 뒤 모델을 사용할 수 있는 일반 역할을 연결한다. 이미 초기 색인이 있는 환경에서는 아래의 시작 명령 두 개만 실행한다.

```powershell
.\product-registration\database\Setup.ps1  # 최초 환경만
.\local\opensearch\Start.ps1
.\.venv\Scripts\python.exe -m product_registration.ops sync  # 최초 색인, API 시작 전
.\analysis-chatbot\scripts\Start.ps1
```

[등록 화면](http://127.0.0.1:8010/products/new)을 열거나 분석 웹의 `商品登録`을 선택한다.

검증에 사용한 원본 DB에는 `GW-LAV06`이 이미 등록되어 있다. 이 환경에서 `ラベンダー苗・6鉢`로 검색하면 등록된 상품을 확인할 수 있다. 실제로 새 상품을 만들 경우 사용하지 않은 다른 코드를 정한다. 검사까지만 연습하려면 마지막 등록 버튼을 누르기 전에 종료한다.

## 한 상품으로 따라가기

짧은 문구도 입력할 수 있다. `バレンタイン用花`를 입력하고 `説明から項目を整理`를 누르면 상품명 후보 `花`와 용도 `バレンタイン用`를 확인할 수 있다. 설명에 없는 수량·중량은 비워 둔다. 상품명·용도·상품 설명이 모두 비어 있으면 화면에서 직접 수정하거나 `確認して類似商品へ`를 눌러 입력 원문으로 검색할 수 있다.

1. **商品を説明**에서 `ベランダ用のラベンダー苗を6鉢入りで登録したい`를 입력한다. 분석 결과의 상품명·용도·기본 단위 표현·입수를 확인한다. 숫자 `６`을 입력해도 수량은 6이어야 한다. 설명에 없는 중량은 비워 둔다.
2. **類似商品を選ぶ**에서 이름·분류·용도와 포장 입수를 비교한다. 후보의 입수가 4라면 차이를 확인하고 참고 상품으로 선택한다. 적절한 후보가 없으면 `コピーせずに入力`으로 계속한다. 검색 서비스 장애 메시지도 이 버튼으로 직접 입력을 이어갈 수 있다.
3. **商品情報を入力**에서 새 코드(예시 `GW-LAV06`)를 입력한다. 원본에 이미 있는 코드라면 다른 코드를 사용한다. `自分の入力`과 `参考商品から` 표시로 출처를 확인하고 내가 지정한 입수 6이 유지되는지 본다. 기본 단위 `鉢`가 없으면 단위의 신규 작성에서 코드와 이름을 입력한다. 상품 분류와 세금 분류도 같은 방식이다. 새 세금 분류는 세율을 만들지 않는다. 이 단계에서 `下書きを破棄`를 누르면 초안이 취소되고 새 마스터와 상품은 저장되지 않는다.
4. `入数` 옆 `?`로 규칙을 확인하고, 연습용으로 수량을 0으로 바꿔 검사한다. **検査・登録**의 오류에서 `修正する`를 눌러 같은 칸에 돌아온 뒤 6으로 고친다. 임시 중량을 지운 경우 빈칸을 유지한다. 검사 뒤 수량이나 규칙이 바뀌면 다시 검사한다.
5. 검사가 통과하면 최종 값과 새 마스터를 확인하고 `登録する`를 한 번 누른다. 상품 코드와 등록 결과가 표시된다. `登録済み・検索反映待ち`는 DB 저장이 끝났다는 뜻이다. 반영 후 새 등록 화면에서 상품명으로 다시 검색해 확인한다.

화면에 `検索にも反映されました`가 표시되면 검색에서도 상품을 찾을 수 있다. [실제 등록 완료 화면](verification.md#실제-등록-완료-화면)에서 발렌타인용 꽃을 등록한 예시와 비교한다.

## 등록 후 검색에 표시되기까지

등록 전용 FastAPI는 서버 측에서 필드·규칙 버전·상품 코드와 현재 마스터 상태를 다시 검사한다. PostgreSQL의 한 트랜잭션으로 상품·신규 마스터·요청 영수증·감사 이력·색인 작업을 저장한다. 같은 요청 번호로 재시도하면 기존 영수증을 돌려준다. 검색 반영 작업은 상품 ID를 OpenSearch 문서 ID로 사용한다.

검색은 일본어 전문 검색과 Titan 임베딩 검색의 **순위**를 합친다. 화면에서 실제 이름·용도·입수 차이도 함께 확인한다. 검색 인덱스가 반환한 후보는 PostgreSQL에서 다시 읽어 현재 선택 가능한 상품만 보여준다.

| 상황 | 담당자가 할 일 |
|---|---|
| 초기 색인 준비 중 | 운영자가 `python -m product_registration.ops sync`를 완료한 뒤 다시 검색한다. |
| 규칙을 확인할 수 없음 | S3 설정·로그인을 확인하고 도움말과 검사를 다시 실행한다. |
| 규칙 버전 변경 | 입력을 유지하고 최신 도움말을 확인한 뒤 재검사한다. |
| 등록 응답을 받지 못함 | 화면의 상태 조회 또는 동일 요청 재시도를 사용한다. |
| 검색 반영 대기 | 로컬 API가 재시도한다. 즉시 처리하려면 프로젝트 가상환경에서 `python -m product_registration.ops retry`를 실행한다. |

동작 상태는 `analysis-chatbot/scripts/Status.ps1`과 `local/opensearch/Status.ps1`에서 확인한다. 실습을 마치면 각 폴더의 `Stop.ps1`을 사용한다. 검증 환경 및 실행 결과는 [상품 등록 검증 기록](verification.md)을 참고한다.
