# 로컬 구현 검증 기록 — 2026-10-12

## 결과

- Python 3.13.15 사용자 설치 + 프로젝트 `.venv`, PostgreSQL 18.6 Windows 서비스, PHP 8.4.25, Node 24.20.0 구성.
- 실제 PostgreSQL의 TPC-H SF1 8개 테이블 적재. 주문 1,500,000행, 주문항목 6,001,215행. 생성 manifest와 적재 행 수 대조.
- Vue/Laravel/Python 전체 경로에서 **고정 샘플 계획 검토 → 승인 → 실제 SQL → 12개월 표·Plotly 막대그래프 → 이력 복원** 검증.
- DB, API, 웹 연결 확인. PostgreSQL은 127.0.0.1:5432, 앱 기본 주소는 http://127.0.0.1:8000.

운영 시험은 별도 인스턴스·18000/18001 포트에서 반복 시작, 다른 작업 디렉터리에서 실행, 상태 확인, 소유 프로세스만 중지, 무관한 프로세스 보존을 확인한다. 브라우저 시험은 18002/18003과 별도 SQLite 두 개를 사용하고 실제 읽기 전용 PostgreSQL 데이터는 공유한다.

브라우저 시험은 PC 폭 1440px과 모바일 폭 390px을 확인한다. 승인 전 결과가 없고, 승인 후 12행과 막대 12개가 표시되며 이력에서 결과를 다시 읽는다. CSRF 없는 POST는 419, 허용하지 않은 Host는 400이다. 초기 AWS 미구성 시 후속 질문이 `AWS_NOT_CONFIGURED`로 표시되면서 이전 결과가 보존되는 것도 확인했다.

## TDD 및 오류 경계

설정, AST 정책, 생성·적재, 실행 제한, 승인 journal, Agent 경계, 수신기, 그래프, FastAPI, Laravel API, Vue 화면, 운영 스크립트의 주요 동작을 먼저 실패시키고 구현 후 통과시켰다. 프레임워크 생성 골격·설치 설정과 이후 추가된 기존 동작 회귀 시험은 별도로 취급한다.

검증한 조건:

- 실제 DB 읽기 전용 트랜잭션·테이블 권한, 정확한 매출 280/공급원가 차감액 60/공급업체 2 fixture.
- 변경 CTE·다중문·시스템 객체·임의 함수·SELECT INTO·잠금 거부, 바인딩 일치 검사.
- 500행 잘림, UTF-8 바이트 제한, SQL 시간 초과 후 다음 조회 정상 작동, 만료 요청 거부.
- SQL 또는 params 변경, 오래된 revision, 중복 승인·중복 수신, 동시 claim, 재시작 중 불명 작업의 재실행 방지.
- 승인 변조 요청이 정상 승인 상태를 오염시키지 않음. 외부 Agent 제출도 한 번만 수행.
- AWS 도구 결과와 Agent 최종 답변 상태 분리. 결과 전송 실패 시 SQL 재실행 없이 outbox 재전송.
- 미구성/비용 정책 미충족/root 인증/잘못된 Agent 응답의 명시적 실패.

시험 중 수정한 문제는 SQLGlot의 AND 분류, 극소 SF0.001 데이터의 복합 키 중복, Windows 프로세스 생성 직후 경로 조회, JSON 날짜 자동 변환, venv 자식 프로세스 종료, WMI 조회 지연과 공유 개발 서버의 요청 간섭이다. 운영·브라우저 시험을 별도 상태와 포트로 분리해 기존 AWS 작업을 보존했다.

## 증거 파일과 한계

- JUnit: `.local/verification/pytest.xml`
- 화면: `.local/verification/home.png`, `result.png`, `mobile.png`
- Playwright 출력: `.local/playwright-results`
- 앱 로그: `.local/logs`; 격리된 시험 로그: `.local/instances/*/logs`

Plotly 기본 배포 모듈은 약 1.08MB(압축 약 359KB)여서 Vite의 500KB chunk 경고가 남는다. 그래프를 표시할 때 지연 로딩하며 초기 앱 JS는 약 79KB다. 브라우저의 JavaScript 오류는 관찰되지 않았다.

한 차례 Windows 네이티브 access violation 진단 출력이 시험 중 관찰됐지만 이후 전체 시험과 종단 시험에서 재현되지 않았다. 원인은 확정하지 않았으며 재현 시 Python/psycopg 네이티브 런타임을 추가 조사해야 한다.

**이 로컬 작업에서 유료 AWS 추론이나 리소스 배포를 실행하지 않았다.** 같은 폴더의 별도 AWS 구축 작업이 공통 계약과 모델·비용 정책·인증·실행 설정을 갱신했다. 완료 시점의 로컬 상태 조회는 AWS 설정 존재와 실행 중인 수신기를 보여주지만, 이것만으로 실제 AWS 왕복 성공을 판정하지 않는다. 실배포·모델·Lambda 왕복 근거는 AWS 작업의 검증 기록을 따른다.

로그인 세션에서의 로컬 실행을 검증했다. 무인 재부팅·인증 자동 갱신·프로덕션 동시 사용자 운영·실제 비용 차단 발동을 완료로 보고하지 않는다. 현재 디렉터리는 Git 저장소가 아니므로 Git 초기화·커밋·푸시는 하지 않았다.
