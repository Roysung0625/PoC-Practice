실행 ID는 `2026-10-12-qa-01`이며, Q-A 실행 구간은 **2026-10-12 19:23:17~19:49:14 JST**다. 중간 평가 도구 복구 시간이 포함된다. 원자료는 [평가 폴더](../../.local/evaluation/2026-10-12-qa-01/), 질문과 독립 정답 SQL은 [cases.json](../../aws/evaluation/cases.json), 재실행 방법은 [평가 도구 안내](../../aws/evaluation/README.md)에 있다.

## 3. 재현된 정확도 문제

### 날짜 기준의 차이와 반복 편차

Q3 1월 주문일 기준 정답은 `476,891,145.7622`인데 모델은 배송일 기준 `472,263,166.9358`을 조회했다. Q3·Q4 각 3건과 Q5 앞선 2건, 총 **8건의 수치 불일치**가 이 차이에서 발생했다. Q6은 날짜 조건이 달라도 고유 수가 우연히 9,998로 같았다.

별도의 독립 SQL로 배송일 기준을 계산한 보조 분석에서는 해당 날짜를 사용한 **11/11건이 일치**했다. [보조 분석 증거](../../.local/evaluation/2026-10-12-qa-01/shipping-date-sensitivity.json). 정답 기준을 사후에 바꾸지는 않았다. 운영에서는 주문일을 기본값으로 명시하거나 날짜 기준을 확인하는 절차가 필요하다.

### 존재하지 않는 판매자 개념 생성

Q10은 세 번 모두 “실제 판매자 계정은 customer 테이블의 고객 계정을 의미”한다고 설명했다. `COUNT(DISTINCT o_custkey)` 등을 `판매자_계정_수`로 이름 붙였다. TPC-H에 고객과 공급업체는 있지만 이 질문이 요구하는 판매자 계정 자료는 없다. **없는 개념을 기존 열로 바꾸어 답하려는 오류**이며, 대체 SQL은 실행하지 않았다. [3회차 원자료](../../.local/evaluation/2026-10-12-qa-01/attempts/r3-Q10.json) · [실제 계획 화면](../../.local/evaluation/2026-10-12-qa-01/browser/r3-Q10.png).

### 원본 수치가 맞아도 설명에서 발생하는 오류

| 사례 | 실제 반환 행으로 계산한 값 | 모델 설명 |
|---|---:|---|
| r3-Q4 월평균 | 463,153,553.804216… → 백만 단위 소수 1자리 **463.2백만** | 약 **463.5백만** |
| r3-Q5 연간 합계 | **3,597,668,196.1099** → 1천만 단위 반올림 **36억** | 약 **35억 8천만** |

평균은 모델이 선택한 배송일 결과 자체로 다시 계산해도 맞지 않는다. Q5 3회차는 SQL이 주문일 기준 정답과 정확히 일치했는데 합계 설명만 틀렸다. 따라서 날짜 기준 차이와 독립적인 산술 오류다. [원본 행 기반 계산 증거](../../.local/evaluation/2026-10-12-qa-01/derived-answer-check.json).

Q3·Q4·Q7의 일부 답변은 데이터에 통화 근거가 없는데 `USD`·`달러`를 추가했다. 일부 답변에서는 할인 매출 또는 공급업체 수를 `contribution`으로 표현했다. 합계·평균은 코드에서 계산한 값을 전달하고, 설명은 검증된 지표 정의·단위·관측 사실만 사용하도록 제한할 필요가 있다.

### 빈 결과 설명의 앞뒤 불일치

Q8의 승인 전 계획은 세 번 모두 “2000년은 1992-01-01~1998-08-02 범위 내”라고 잘못 설명했다. 실제 SQL은 0행을 반환했고 최종 답변은 데이터가 없다고 설명했다. 최종 답변이 바로잡혀도 사용자가 승인할 때 보는 계획의 오류는 별도로 남겼다. [빈 결과 화면](../../.local/evaluation/2026-10-12-qa-01/browser/r3-Q8.png).

## 4. 실제 연동·성능·사용량

계정 `551013419462`, 도쿄 `ap-northeast-1`, `deepseek.v3.2`를 사용했다. 앱과 수신기는 각각 `poc-chatbot`, `poc-worker`의 일반 IAM 역할로 인증했다. 모델·프롬프트·IAM·인프라·예산 정책은 변경하지 않았다.

- Lambda 소규모 왕복: 국가 3행이 같은 호출 응답으로 반환됐고 동일 요청 반복의 결과도 같았다. [lambda.json](../../.local/evaluation/2026-10-12-qa-01/checks/lambda.json).
- 실제 Q-A SQL 24건: 모든 요청에서 native tool 사용, SQL 성공, AWS 전달, Agent 설명 성공, 원본 행과 도구 응답 일치를 확인했다.
- Titan V2: 실제 호출 1회, 1,024차원, norm `0.9999999846146388`, 입력 10토큰. 벡터 검색은 검증 대상이 아니다. [embedding.json](../../.local/evaluation/2026-10-12-qa-01/checks/embedding.json).
- 원본 차트가 있는 12건은 축·값이 반환 행과 일치했다. 빈 결과 3건은 차트가 없었다. 실제 브라우저에서는 대표 5개 대화를 다시 열고 표 셀·답변·막대 수·빈 결과·계획 표시와 새로고침 후 복원을 확인했다. JS 오류는 0건이었다. [화면 검증 기록](../../.local/evaluation/2026-10-12-qa-01/browser/verification.json).

## 5. 평가 도구·증거와 후속 작업

추가한 도구는 독립 기준값 고정, Laravel API 경유 실행, 의미별 열 매핑, Decimal 비교, 설명 검토 근거, 도구 사용 증거, 브라우저 재확인, CloudWatch 사용량 수집을 지원한다. 공개 앱 API는 변경하지 않았다. 기존 실제 연결 probe에는 결과를 새 폴더에 저장하는 선택 옵션만 추가했다.

처음 실행에서 Laravel의 빈 매개변수 객체가 JSON 배열 `[]`로 표현되어 평가 도구가 승인 전에 멈췄다. Python·Laravel 실행 기록 모두 0건임을 확인한 뒤 도구의 표현 처리만 고쳤고, 같은 모델 계획을 재사용했다. 완료된 질문을 다시 생성하지 않았다. 오류와 복구 근거는 `r1-Q8.json`의 `harness_events`에 있다. 중간 종료 후 기준값 재확인도 한 번 20초 제한에 걸렸으나, 최종 실행 후에는 모든 정답 조회가 성공했고 시작/종료 기준값이 완전히 일치했다.

연도/월 분리 열과 한국어 별칭은 모델 오답으로 처리하지 않았다. 원본 SQL 표현식에 근거해 매핑하고 오프라인으로 다시 채점했다. 최초 자동 판정은 각 attempt에, 최종 판정은 `summary.json`에 보존했다. 모델에 재질문하거나 답변을 고쳐 점수를 올리지 않았다.

후속 수정의 우선순위:

1. 날짜 기준을 계획에 명시하고, 기본값 또는 확인 질문으로 주문일/배송일의 모호함을 해소한다.
2. 판매자 계정처럼 없는 개념은 임의 매핑하지 않고 산출 불가로 응답한다.
3. 합계·평균은 코드에서 계산하며, 단위와 매출/공급원가 차감액 정의를 설명 단계에 고정한다.
4. 카탈로그 날짜 범위를 코드로 검사해 승인 전의 잘못된 데이터 존재 설명을 막는다.
5. 약 20초까지 걸린 SQL의 실행 계획과 부하를 확인한다.

앱이나 프롬프트 수정은 이번 평가 범위에 포함하지 않았다. 실제 인증 취소·공유 수신기 중지·네트워크 단절은 수행하지 않았고 기존 모의·격리 시험으로만 확인했다. Windows 재부팅·무인 실행·벡터 검색·실제 예산 차단 발동은 미검증이다.
