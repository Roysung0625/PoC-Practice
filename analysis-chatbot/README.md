# 대화를 이어가는 DB 분석 챗봇

질문을 해석하고 실제 테이블 문서를 읽은 뒤 조회 계획을 제시합니다. SQL을 승인하면 표·검증 결과·통화별 PNG·관측 설명을 한 대화에 저장합니다. 새로고침과 서버 재시작 후에도 대화와 산출물을 다시 열 수 있습니다.

새 웹은 **http://127.0.0.1:8010**, 공용 Python API는 **http://127.0.0.1:8001**입니다. 기존 웹(8000)·DB·승인 원장을 유지합니다. 현재 분석 대상은 `poc_idempiere`의 GardenWorld 데모와 912개 테이블 문서입니다.

**현재 AWS Agent runtime v13·DEFAULT 버전13 `READY`, stack `UPDATE_COMPLETE`입니다. 최종 Python 전체 통합661개가 통과했고 변경 없는 독립 가시화61개·Vue10개·Laravel10개(71 assertions)·TypeScript/Vite 빌드 결과도 유지합니다.** v13 실제10문항은 독립 수치9/10·수동 전체4/10으로 종료됐습니다. 최초 초안9통과·1거부, 실제1회 보완은 실패했습니다. 원본 실패·독립golden·소스 지문은 보존합니다. 이후 로컬 수정으로 저장된 차트 실패4사례의 PNG7개를 복구하고 실제 화면과 API 단독 재시작 복원을 확인했으며 추가 모델/SQL 호출은0입니다. 이 사후 복구를 실제 AWS 전체 통과에 합산하지 않습니다. 승인 전 지정된 검증 거부만 같은 조건으로 최대1회 초안을 보완하며 첫 거부와 최종통과를 따로 표시합니다. 승인 후 SQL 자동 재실행은 없습니다. 웹·API·DB·PNG는 계속 로컬입니다. [질문별 판정·개선 효과·한계](docs/VERIFICATION.md) · [배포 검토](docs/DEPLOYMENT_REVIEW.md) · [교육](../docs/education/README.md).

## 실행

기존 `.local/app.env`, 읽기 전용 iDempiere DB, 프로젝트 `.venv`, Node 24.20.0 및 Composer를 사용합니다. PHP 8.5.12는 새 전용 디렉터리에 설치하며 기존 PHP와 글로벌 PATH를 바꾸지 않습니다.

프로젝트 루트의 PowerShell:

```powershell
# 최초 설치. Composer/npm/가시화 Python 의존성을 잠금 파일로 설치합니다.
.\analysis-chatbot\scripts\Setup.ps1

# 웹과 API 시작. 기존 API는 새 계약 버전을 확인한 뒤 재사용합니다.
.\analysis-chatbot\scripts\Start.ps1
.\analysis-chatbot\scripts\Status.ps1
.\analysis-chatbot\scripts\Check.ps1

# AWS runtime 배포·로컬 AWS 인증 구성 후 수신기도 시작할 때
.\analysis-chatbot\scripts\Start.ps1 -Receiver

# 이 스크립트가 시작한 프로세스만 중지
.\analysis-chatbot\scripts\Stop.ps1
```

`Setup.ps1 -SkipInstall`은 이미 설치된 의존성으로 환경 파일·마이그레이션·웹 빌드를 준비합니다. 기존 APP_KEY를 유지하고 DB 데이터를 재생성하지 않습니다. 실행 파일은 `$PSScriptRoot` 기준으로 찾으므로 다른 작업 디렉터리에서도 호출할 수 있습니다. 새 프로그램은 Windows 로그인 세션에서 실행됩니다.

## 사용 순서

1. 왼쪽에서 새 대화를 열고 질문을 보냅니다. AI 분석은 기간·대상·지표를 다시 말하며, 모호한 조건은 확인합니다.
2. 실제로 읽은 테이블과 관계, 모델 호출과 SQL 단계를 시각과 함께 `분석 과정`에서 확인합니다. 이 목록은 서버 이벤트이며 모델의 내부 사고과정이 아닙니다.
3. 적용 조건·테이블·조인·지표·SQL·매개변수를 읽고 `확인 · 조회 실행`을 누릅니다. 새 SQL은 승인한 한 문장만 실행합니다.
4. 원본 표, 검증 상태, 통화별 PNG와 다운로드, 관측 사실·한계·후속 질문을 확인합니다. 0행은 정상 빈 결과이며 차트를 만들지 않습니다.
5. 같은 입력창에서 질문하면 직전 결과를 참조하는 표시가 나타납니다. 오래된 결과는 `이 결과에서 이어서 질문`으로 지정합니다. `참조 결과 해제`는 새 분석을 시작합니다.
6. `다른 그래프로 보기`와 `다시 설명하기`는 저장 결과를 사용하며 SQL을 다시 실행하지 않습니다. 기간·지표·상세 데이터 변경에는 새 계획과 승인이 필요합니다.

로컬 연결 검사는 고정 SQL을 사용하는 기능 검사입니다. 입력한 자연어를 AI가 분석하거나 기간 변경을 해석한 것으로 표시하지 않습니다. 일반 질문의 검증 결과는 독립 정답 SQL과 대조하기 전까지 **미검증**입니다.

## 제한과 복구

- 후보 테이블 12개, 상세 문서 32개, 관계 2홉, 문서 컨텍스트 128KiB. 원본 문서를 전체 읽고 해시를 확인한 뒤 중복 FK 주석·검증된 중복 Mermaid·링크 주소만 제거한 문서 투영을 최종 모델에 전달합니다. 모든 열·부모/자식 FK·조회 주의를 보존하고 투영 버전·실제 전달 컨텍스트 해시를 검증합니다.
- 계획은 모델 6회·누적 180초로 제한하며 답변 대기는 제외합니다. 문서 계획 단일 호출 제한은 90초이며 누적 한도는 유지합니다. SQL 요청 만료 60초, DB 실행 최대 20초·500행·결과 크기 한도를 유지합니다.
- 차트 단위·그룹 차원은 SQL과 물리 열 근거로 검증합니다. 금액은 연결된 통화, COUNT는 건으로 표시하고 모델이 쓴 제목·축의 단위는 중립적인 호스트 표기로 바꿉니다. 수량 UOM·복잡한 표현식의 단위가 확인되지 않으면 미검증으로 남기고 단위별 최소·최대 통계 설명을 생성하지 않습니다. 복합 그룹은 모두 라벨에 반영하며 모호한 중복 라벨은 거부합니다.
- 후처리는 전체 90초, PNG 15초, 설명 60초입니다. 설명 문장의 수치 근거는 원본에서 계산한 관측값과 대조합니다.
- 한 대화의 진행 작업은 하나입니다. 중복 요청 ID는 같은 작업을 반환합니다. Python의 AWS 호출 제한과 기존 수신기 하나를 공유합니다.
- 이미지 실패 시 원본 표, 설명 실패 시 원본 표·이미지를 보존합니다. `후처리만 다시 시도`는 SQL을 재실행하지 않습니다.
- 취소는 이후 단계를 중지합니다. 이미 실행 중인 SQL의 물리적 중단을 확인 없이 주장하지 않습니다. 재시작 중 불확정 작업은 중단 상태로 남기고 자동 재실행하지 않습니다.
- 연결이 끊기면 저장된 대화는 유지됩니다. `Status.ps1` → 로그 확인 → 소유한 API/웹만 중지·재시작 → 화면 새로고침 순으로 복구합니다. 기존 스크립트로 시작한 API는 해당 스크립트로 재시작해야 합니다.
- AWS 인증 만료는 기존 로그인 절차를 사용합니다. 로컬 웹 중지/시작은 AWS 인증을 갱신하지 않습니다. 수신기를 다른 PC와 동시에 실행하지 않습니다.
- 월 25 USD 초과 차단과 10 USD 알림은 기존 설정을 그대로 사용합니다. 새 리소스 생성·배포는 별도 승인 대상입니다.
