# 월 25 USD 초과 감지 후 자동 차단

사용자 승인: 계정 전체 실제 집계 비용이 25 USD를 초과하면 자동 차단한다. AWS 집계·알림 지연으로 초과 과금이 생길 수 있음을 허용한다. 정확한 청구 상한을 보장하지 않는다.

## 구현

1. 기존 월 25 USD 예산과 10 USD 알림을 보존한다. ACTUAL / GREATER_THAN / ABSOLUTE_VALUE / 25 알림을 SNS에 추가한다.
2. CloudFormation으로 SNS, 제어 Lambda, 15분 EventBridge 점검, IAM 차단 정책, 복구 기록용 비공개 S3를 배포한다.
3. Lambda는 Budgets 실제 집계액을 재조회한다. 25 초과 시 차단 상태를 기록하고 일반 IAM 사용자·역할에 전체 API 거부 정책을 붙인다. 제어 역할과 AWS 서비스 연결 역할은 제외한다. root는 IAM 정책으로 제한할 수 없다.
4. 활성 리전의 Auto Scaling, ECS, EC2, RDS, Lambda 실행을 중단한다. 중단 전 설정을 S3에 보존한다. 실패는 명시적으로 보고하고 15분마다 재시도한다. 삭제 작업은 하지 않는다.
5. 비용이 다음 달에 초기화되어도 차단을 유지한다. root가 점검을 일시 중지하고 기록을 확인한 후 수동 복구한다.

## 검증

- 로컬 시험: 25 이하/초과 경계, 부정확한 입력 거부, 차단 상태 유지, dry-run 비변경, 실패 보고, 복구 기록 보존.
- AWS: 템플릿 검증, 배포 상태, 실제 예산·SNS 연결·스케줄 확인, 실계정 dry-run, SNS 전달 로그, IAM 정책 시뮬레이션.
- 실계정의 비용을 인위적으로 늘리거나 전체 서비스를 시험 중단하지 않는다. 실제 초과에 의한 전체 중단은 미시험이라고 보고한다.

## 범위와 한계

계정 전체 예산·일반 IAM 주체를 대상으로 하지만 AWS의 모든 과금 항목을 제거하지는 않는다. root, 서비스 연결 역할, 이미 진행 중인 실행, 저장소·스냅샷·IP·지원·구독 비용은 남을 수 있다. 새 서비스 도입 시 해당 서비스의 중지 API를 검토한다. 프로젝트 앱은 일반 역할로 실행해야 차단 정책이 적용된다.
